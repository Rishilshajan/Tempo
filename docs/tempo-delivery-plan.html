Tempo: build breakdown

An agentic personal task manager that keeps your day in rhythm - it captures tasks with almost no friction, sorts them by what actually matters, warns you before important work slips, and hands you a clear plan each morning.

ProductTempo Author Rishil Shajan Team SDE + TPE Date 02 October 2026 Estimate ~11.5 working days
1

What we are building

Tempo manages your task list with you, rather than just storing it. It is built for juggling personal, financial and multiple work tracks at once, where important things quietly slide to "tomorrow" and a flat single list stops working.

  1. You add a task in plain language, typed or spoken (for example "draft pitch memo before 11am for @alpha, 45m"). The app turns it into a structured task: title, date, time hint, duration and domain.
  2. Tasks are grouped into Today, Rolled-Forward and Upcoming, and can be viewed as a List, a Board (columns by status), or a Calendar (tap a date to see that day).
  3. Each task can belong to a domain (a startup, personal, financial) and can block another task, so slippage cascades to what depends on it.
  4. Anything not finished rolls to the next day and is flagged loudly (for example "pushed 3 times - still real?").
  5. Each morning the app assembles a priority-ordered, time-stamped plan tuned to your productive window, and warns when too much clusters into the same slot.
  6. You can open a plain list of the exact rules that trigger each warning, so nothing the app does is hidden.
The idea in one line
You supply the judgement; the app supplies the vigilance and the time math.

The bulk of the work is the frontend (the screens, the three views and the capture flow). The backend holds the agent logic. The database and infrastructure are both small.

Phase 1 - Foundation + data layer ~1.5 days (12 hr)

Stand the project up end to end: app online, brand in place, database shaped.

FE Scaffold + design tokens ~4 hr

  • Next.js (App Router) + Tailwind + component library + Figtree font.
  • Sage Focus palette as CSS tokens (sage brand, deeper green for buttons, status colours).

DB Schema + migration ~2 hr

  • Five tables with Drizzle; generate and apply the first migration.

Infra Supabase + deploy skeleton ~2 hr

  • Create the Supabase project, wire the connection string, push the schema, and get a skeleton live on the host.

FE Cold-start splash + installable shell ~4 hr

  • Branded 3-second splash on every cold start, then land on the dashboard; app manifest and icons. (Phase tasks 4 + 2 + 2 + 4 = 12 hr.)

The navigation frame and the first-run experience, working on both desktop and mobile.

FE Responsive shell ~6 hr

Phase 3 - Tasks, domains + three views ~3 days (24 hr)

The core manager: create tasks, group them into domains, and see them three ways.

BE Task + domain save/load ~6 hr

  • Create, read, update, delete for tasks and domains via server actions; one guard on status moves.

FE Domains in Settings ~3 hr

  • Create, rename, recolour and delete domains; assign a domain when adding a task.

FE List view ~3 hr

  • Flat, filterable list with domain colour tags and status.

FE Board view ~6 hr

  • Columns by status (not started, in progress, done, rolled-forward); move a card between columns; horizontal snap-scroll on mobile.

FE Calendar view ~4 hr

  • Month grid; tap a date to filter to that day's tasks.

FE Task detail drawer ~2 hr

  • Title, description, sub-steps, domain, status, due date, time hint and duration. (Phase tasks 6 + 3 + 3 + 6 + 4 + 2 = 24 hr.)

Phase 4 - Agentic layer ~3 days (24 hr)

The part that makes Tempo more than a list: parsing, inference and honest warnings. Kept server-side so the key stays secret and the rules stay in one place.

BE Natural-language quick-add ~6 hr

  • Turn free text into a structured task (title, date, time hint, duration, domain) via a hosted language model behind a server endpoint.

FE Voice capture ~3 hr

  • Browser speech-to-text feeds the same quick-add; handle no-permission and unsupported-browser cases.

BE Importance inference + dependencies ~5 hr

  • Walk the dependency graph; a task that blocks a deadline inherits urgency even when it was labelled flexible.

BE Conflict + clustering detection ~6 hr

  • Flag serious clashes and time-hint clustering ("three before-noon tasks will not fit"); ignore flexible overlaps; all driven by editable rules.

FE Auditable rules screen ~4 hr

  • A plain list of the exact conditions that trigger warnings, with toggles. (Phase tasks 6 + 3 + 5 + 6 + 4 = 24 hr.)
7

Phase 5 - Rollforward, briefing + alerts ~2.5 days (20 hr)

The daily rhythm: nothing hides, the morning plan writes itself, and reminders land on time.

Infra Nightly rollforward job ~4 hr

  • Scheduled job moves unfinished tasks to the next day and increments their push counter.

BE Morning briefing ~5 hr

  • Assemble a priority-ordered, time-stamped plan for the productive window and phrase it in plain language.

FE Briefing UI + loud rolled flags ~3 hr

  • Surface the briefing on Today; show "pushed N times" prominently on rolled-forward items.

FE + Infra Alerts + push ~4 hr

  • Web push plus user-set alert times; a notification fires when important work is slipping.

BE Google Calendar awareness ~4 hr

  • Read calendar events so conflict detection can see real commitments. (Phase tasks 4 + 5 + 3 + 4 + 4 = 20 hr.)

Why this is realistic
The stack is re-used end to end - server actions, Supabase and a ready component library carry the plumbing, so effort concentrates on the two things only Tempo does: the three task views and the agent rules. The frontend is honestly the bulk; the database and infrastructure stay small by design.
9

Watch-items (small, but do not skip)
  • Rollforward must never drop or duplicate a task - it only moves unfinished ones and increments the counter.
  • Dependency cascade: when a blocking task slips, the blocked task's urgency has to update in the same pass.
  • Clustering warnings are about pressure, not hard alarms - do not over-warn on flexible or gig-style tasks.
  • Settings is a single row now; adding per-user columns and row-level security later must stay a clean, additive change.
  • Voice capture depends on the browser speech API - degrade gracefully when it is missing or denied.
